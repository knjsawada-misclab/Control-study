# プロトコル会話シミュレータ

機械情報システム入門 (学問の扉) ／大阪大学 澤田賢治

ネットワークプロトコルの**コマンドと応答の繰り返し**をチャット風の UI で1ステップずつ確認できるシミュレータです．SMTP・HTTP・DHCP・Modbus/TCP の4つのプロトコルに対応しています．

> **対象**：Wireshark 演習の前に，各プロトコルの「会話の順番」を理解するためのシミュレータです．Telnet による SMTP 送信演習の予習にも適しています．

---

## デモ / 使い方

付属の `protocol_conversation_simulator.html` を **ブラウザで開くだけ**で動作します (外部ライブラリ不要・オフライン可)．

操作のポイント：

- **プロトコル選択** で SMTP / HTTP / DHCP / Modbus/TCP を切り替え．
- **次のステップ ▶** ボタン (または→キー / スペースキー) で会話を1つずつ進める．
- **◀ 前のステップ** で戻る．**全て表示** で一括表示．
- クライアント側のメッセージは**青い吹き出し** (左)，サーバ側は**緑の吹き出し** (右) で表示．
- TCP ハンドシェイクは**灰色**で区別される．
- 下部の**ステップ詳細**パネルに，各ステップの OSI 層・日本語解説・Wireshark フィルタが表示される．

## 各プロトコルの会話構造

### SMTP (メール送信，25/tcp)

16 ステップの会話．Telnet で手動送信する際と同じ流れです．

| # | 方向 | コマンド / 応答 | 意味 |
|---|---|---|---|
| 1-3 | TCP | SYN → SYN+ACK → ACK | 3ウェイハンドシェイク |
| 4 | ← | 220 ESMTP | サーバの挨拶 |
| 5 | → | EHLO student.local | クライアントが名乗る |
| 6 | ← | 250 Ok | 了解 |
| 7 | → | MAIL FROM: | 送信者指定 |
| 9 | → | RCPT TO: | 受信者指定 |
| 11 | → | DATA | 本文入力開始 |
| 12 | ← | 354 | 本文を入力してください |
| 13 | → | 本文 + . | 本文送信，.で終了 |
| 15 | → | QUIT | セッション終了 |

### HTTP (Web 閲覧，80/tcp)

7 ステップ．GET 要求 → 200 OK 応答のシンプルな流れです．

### DHCP (IP 自動取得，67-68/udp)

4 ステップ (DORA)．TCP ハンドシェイクなし (UDP のため)．

| # | 方向 | メッセージ | 意味 |
|---|---|---|---|
| 1 | → | Discover | DHCPサーバを探す |
| 2 | ← | Offer (IP:192.168.1.180) | このIPを使えます |
| 3 | → | Request | そのIPを使います |
| 4 | ← | Ack (Lease:3600s) | 利用を許可 |

### Modbus/TCP (制御通信，502/tcp)

9 ステップ．HMI (192.168.1.10) と PLC (192.168.1.195) の通信を再現．

- FC03 (Read Holding Registers)：SP・PV・MV の読み取り
- FC06 (Write Single Register)：SP 値の変更

## Wireshark 演習との対応

各ステップの詳細パネルに Wireshark の**表示フィルタ例**が表示されます．

| プロトコル | フィルタ例 |
|---|---|
| SMTP | `smtp` または `tcp.port == 25` |
| HTTP | `http` または `tcp.port == 80` |
| DHCP | `dhcp` または `bootp` |
| Modbus/TCP | `mbtcp` または `tcp.port == 502` |

---

## 学習のポイント

- **コマンド暗記より「会話の順番」を理解する**ことが重要
- SMTP は「コマンド → 応答」の繰り返しで進む
- DHCP は UDP のため TCP ハンドシェイクがない
- Modbus/TCP はマスタ (HMI) が聞かないとデータが来ない (ポーリング方式)
